# HBR 研究室

本地运行的炽焰天穹养成记录与排轴工具，当前版本 **0.12.2**。包含 Box、排轴器和 Boss 资料三个页签，可独立使用，也可接入风子工作台。

## 启动

需要 Python 3.10 或更新版本，服务仅使用标准库，无需安装 Python 第三方包。开发测试和目录更新还需要 Node.js 20 或更新版本。

```powershell
python -B hbr_app.py
# 只启动本机服务：
python -B hbr_app.py --serve
# 指定独立数据目录：
python -B hbr_app.py --data-dir "./local-data"
```

Windows 也可双击 `启动研究室.vbs`。默认地址为 `http://127.0.0.1:8787`，服务只监听本机。程序寻找 `FUUKO_HOST` 指定的窗口程序、同级风子工作台或旧 Shared 宿主；找不到则用默认浏览器打开。服务和网页所需的 `shared/` 已内置。

在风子工作台的“管理”中导入本项目 `workbench.json`，即可登记为工作台。说明文件使用接入协议 1，支持数据目录传入、运行状态和正常关闭。

## 功能

- **Box**：显示 SS/SSR 卡面和拥有、突破状态，可按部队、稀有度、拥有状态及名字筛选；编辑角色共通养成与单卡养成。一键导出密排 Box PNG，可选每行数量、主题和是否显示未拥有卡面。
- **从游戏同步**：只读本机客户端缓存，识别已有养成与编队。缓存可能滞后于游戏；同步前保存快照，未识别项保持未知。可通过 `HBR_CACHE_DIR` 指定缓存位置。不登录账号、不抓包、不操作游戏进程或文件。
- **排轴器**：选期数后点“求最佳轴”，以现有编队和已拥有卡面为起点搜索队伍、技能、装备、特殊规则及战术卡，显示按模型评分排列的候选方案与逐回合行动。默认保留 10 个结果，可选 5 / 10 / 20 个；可切换到次优方案，选择和结果会保存。
- **核对已知配队**：在“更多细致选项 → 从游戏编队导入”选好队伍，点“按这队原装搜轴”。搜索使用这六人的装备、支援卡、面板和已装技能，可比较不同前卫与行动顺序。要让搜索调整装备和技能，保留“固定当前六人”并取消保留配置。打开成员的“配置与面板”，可以核对或替换库存里的专属宝玉和各属性吊饰。
- **搜索稳定性**：按固定批次和候选数量搜索，相同输入（含已有轴）、种子与搜索预算可重现；线程完成先后和机器负载不再决定搜索到哪一批。再次搜索会重评并保留兼容的已有轴，提高投入可探索更多队伍并加宽排轴搜索。快/标准/深入最多改进 48/144/360 个候选；固定配队或可用组合耗尽时会提前完成。
- **成功率下限**：可设置 0–100%（0 表示不限），默认以照轴完成率判定，也可选含续打的通关率。先筛选完整的精评结果再取前 N 个；旧结果可即时筛选。没有合格方案会明确提示，有限样本中的 100% 不是实战保证。
- **敌方参数**：搜索、手排回放、伤害计算器与快速排轴共用同一组 DP/HP/能力值；支持从本机静态参数补充文件读取遭遇战各难度、阶段的数值，并按原始敌人槽位对应。主界面显示来源，也可填写实测覆盖值。缺少难度表时明确提示使用未校准的基础值，不猜测倍率。模型、参数或计分设置变化后的旧成绩需重新搜索复评。
- **长时联合搜索**可选 15 分钟、1、3、6 或 12 小时。在已通关的轴上试换饰品、支援卡、增幅器和芯片，轮换六个位置的人选，再调整实际技能、站位、OD 和跨阶段战术卡。固定六人仍可换装，另勾保留配置时只优化轴及允许的规则与战术卡。轮次完成后，当前浏览器会保存候选及进度。暂停或关闭页面后，用相同条件再次求解可继续。达到目标时长后，程序完成当前轮并用独立样本复核入围轴。
- 长搜轮换 7、18、12、32 四种精排束宽。连续搜索也会扩大局部改动范围，每个入选父轴最多试 512 个改法，单轮沿用轴换装或换人最多复评 512 个候选。
- **评分**只用通关样本计算均分和分位数，失败率与成功样本数单独展示。快、标准和深入分别复评 24、32 和 40 次。长时搜索默认每条轴复评 40 次，最终入围轴再各用 96 个独立样本排名。遭遇战结果显示按每阶段一回合及伤害计分封顶推得的上限，实际队伍能否达到该分数仍取决于战斗。
- **队伍属性**：可选冰、火、雷、光、暗、无属性，按主要技能伤害属性筛选结果。不会要求六张卡面都属于同一属性，跨属性增伤、充能、减益和治疗角色仍可参选。
- **排轴与配置详情**：普通、追加及每轮 OD 各占一行，三名成员的行动按次序并列，破盾、击杀、前开/后开 OD 标在对应行，并注明当前暴击/伤害预测假设；平均伤害预测不代表每次实战都能击破。每次行动显示所有目标扣除 DP/HP 的合计，不是单个敌人的伤害跳字。配置默认展开，列出技能、饰品强化与词条、孔位及支援卡面、突破和共鸣特性；未知数据与模型推算分开注明。
- **更多细致选项**：搜索投入与目标、固定当前配队、规则选择、宝玉和战术卡设置、逐回合设计器、快速排轴、伤害计算器与公式来源。
- **Boss 资料**：查看公开数据中的期数、敌人、规则与行动资料。当前数据覆盖范围以随附目录为准。

搜索采用有界束搜索和启发式配队，结果是本次搜索找到的较优解，不保证全局最优或穷举所有可行队伍。分数、成功率和伤害均来自模拟；有限随机样本不证明游戏中必定成功。受击、敌方行为、部分特殊机制和计分仍有近似或待实测之处，不能将模拟结果视为真实游戏成绩。

职责标签不等于实战作用，配队不采用固定的输出、辅助人数模板；实际技能与模拟贡献决定候选价值。“按轴完成”要求照给定计划合法行动并通关；“通关”还包括每阶段最多 2 个回合的自动续打。普通回合、每一轮 OD 和追加回合均在行动前同时选招。本轮队友给的 SP 要到下一次选招才能用来选择原先付不起的技能。允许非负 SP 透支的技能和「速弹」按各自条件判断，回放在对应行动下标明原因。若选招后费用上涨且结算时付不起，模型暂将该轴排除；此边界仍待实测。SP 或 OD 不足等非法行动不会被计为成功，也不会作为零分拉低通关均分；这两种样本成功率都不是实战保证。“最高分”按通关均分排序，“最稳”仍优先成功率。

遭遇战深搜会比较多条跨阶段路线，保留能为后续敌人留 SP、OD 和限次技能的方案。挑选战术卡时也会整组尝试能一起触发的卡。固定六人搜轴时，如果随机重放中 SP 或 OD 不足，搜索会尝试更改技能、调整 OD 时机或增加明确写入轴中的普通回合，然后重新评估成功率。

单体辅助可指定队友。若预计提前击杀，排轴会标出当轮剩余成员可用的零耗备用行动。山脇的「魔界骑兵」显示在实际发动的位置，可在前开 OD 之前蓄量表，也可在 OD 内使用，全程共三次。切换六人卡面或站位顺序时，手排轴随原队伍保存。

技能可以带手选属性、按队伍状态自动变化，或随机发动不同招式。手选分支分别参与搜索，共用一个装备格和技能次数。自动分支会读取对应技能的使用历史、场上存活敌人数和实际状态。例如山脇要凑齐六名「小跟班」才能使用「超级大爆炸」，逢川惠的「小玉合奏」在有队友破盾的普通回合开始时自动发动。自动技能在三人的行动之前单列显示。

装备伤害限制器的成员可以在逐回合设计器里勾选本次主动攻击限伤。导入编队时只读取有无装备，旧轴和冲分搜索默认关闭。回放在对应行动标出「限伤开启」。

逐轴回放下方可展开模拟实际遇到的未支持或近似机制。部分随机技能按公开的概率范围估算，特殊追击、战斗开始时的干劲分布、部分异常状态仍需实战校准。

多段受击按命中顺序扣除我方 DP 或 HP，公开数据缺少各段权重时按段数均分。下一阶段沿用剩余量表。未用完的 OD 行动轮能否带入下一战仍待实测，当前模型不额外计入。

## 数据与图片

新安装的数据目录默认为当前用户的 `%LOCALAPPDATA%/FuukoWorkbenches/hbr`；非 Windows 使用用户本地数据目录。`--data-dir` 优先于 `HBR_DATA_DIR`。原位维护安装仍可沿用同盘已存在的旧数据目录；带 `SOURCE-MANIFEST.json` 的干净源码发布不会自动选取该旧目录。个人档案为 `archive.json`，保存时生成轮转备份，重要导入另存快照。菜单提供 JSON 导入、导出及打开数据目录。

`public/data/` 仅包含 hbr.quest 的公开目录。默认 Git 源码包不附带可下载的卡图，缺图时显示占位。补齐图片：

```powershell
python -B scripts/download_images.py
# 仅检查引用，不联网：
python -B scripts/download_images.py --dry-run
```

工具只下载目录中列出的公开 CDN 图片，检查路径、格式及已记录的 SHA-256；不覆盖哈希不符的已有文件。图片保存在 `public/assets/hbr/`，默认被 Git 忽略。`Update-Images.ps1` 是同一工具的 Windows 包装，可在 Windows PowerShell 5.1 使用。

基础目录更新：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Update-Catalog.ps1
```

该命令下载基础角色、卡面和装备表并补图。战斗技能、面板与 Boss 数据有独立构建入口：`scripts/build-skills.py`、`scripts/build-stats.py`、`scripts/build-bosses.py`；用 `--help` 查看输入选项。数据更新不会替换个人档案。游戏素材与社区公式的来源说明见 [NOTICE.md](NOTICE.md)。

遭遇战的敌人基础表不等于所选难度的阶段参数。若已有从本机静态资源副本导出的 `MasterWaveBattle.json`、`MasterWaveBattleStage.json`、`MasterWaveBattlePhase.json`、`MasterBattle.json`（每个文件为含 `items` 的对象），可生成本机补充文件：

```powershell
python -B scripts/build-wave-parameters.py --tables-dir "./local-tables" --out "./local-data/enemy-parameters.json" --report "./local-data/enemy-parameters-report.json"
```

输出放在研究室实际使用的数据目录，重新打开页面后加载。构建器校验活动、难度、阶段和敌人原始槽位的关联；有缺值的整个难度跳过，不推算补齐。此文件与原始静态表不随 Git 源码发布，运行服务无需解析资源的第三方依赖。覆盖既有输出需另用 `--overwrite` 明确指定；个人档案不受影响。

## 验证

```powershell
node --test tests/*.test.mjs
python -B -m unittest discover -s tests
```

测试使用合成输入、公开数据和临时服务目录，不读取真实游戏账号缓存。测试覆盖模型行为、存档保护、服务接口、目录构建、搜索筛选、发布隔离等；这些检查不等于游戏内实测验证。

## 独立源码发布

```powershell
python -B scripts/package_release.py --output "release/hbr-planner-source"
# 或生成源码 ZIP：
python -B scripts/package_release.py --output "release/hbr-planner-source.zip"
```

只在导出的源码目录初始化和提交 Git 仓库。白名单保留维护源码、公开主数据、正式构建工具和可重复测试，排除 AI 工作记录、历史状态、临时脚本、个人档案、截图、缓存、旧启动器和二进制宿主。本机应用图标在导出时换为通用几何图形，源文件保持原位。

`SOURCE-MANIFEST.json` 记录每个发布文件的 SHA-256。导出前扫描用户路径、机器标识、邮箱及常见凭据格式；它不能代替最终人工复核。`--refresh` 只更新无手改、无额外文件的先前导出，已初始化 Git 的目录应使用新的输出位置。可选 `--include-images` 仅打包目录所列且通过公开来源哈希验证的卡图。

`.gitattributes` 禁用 Git 自动换行转换，使首次提交和跨平台克隆保留文件字节及清单中的 SHA-256；文本差异仍可正常查看。

项目尚未选择开源许可证。生成源码候选不会创建远程仓库、提交、推送或上传个人数据。
